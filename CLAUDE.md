# Правила для Claude Code в этом репозитории

## Данные

**Этот репозиторий публичный.** Реальные экспериментальные данные хранятся
в отдельном приватном репозитории и НИКОГДА не коммитятся сюда — ни в `main`,
ни в ветку, ни в pull request. Ветки и PR публичного репозитория видны всем
и остаются в истории навсегда даже после удаления ветки, поэтому один
случайный коммит нельзя «откатить» — данные станут публичными немедленно.

Конкретно запрещено добавлять в этот репозиторий:

- файлы измерений (ВАХ, C–V, Холл, рентген, АСМ) в любом формате
- числовые параметры конкретных образцов в исходном коде — геометрию мезы,
  толщины слоёв, концентрации, измеренные коэффициенты
- идентификаторы образцов в коде, тестах, примерах и документации
- абсолютные пути к каталогу с данными
- имя приватного репозитория с данными

Доступ к данным идёт только через `mesa_diode/config.py`, который читает
путь из переменной окружения `MESA_DATA_DIR`. Параметры образца берутся
из `samples/<id>/meta.yaml` в каталоге данных, а не из исходника.

Когда обе папки подключены к одной сессии, перед каждым коммитом проверяй,
в каком репозитории находишься.

## Тесты

В тестах используются только синтетические данные, посчитанные самой моделью
с заранее известными параметрами. Тесты не должны требовать `MESA_DATA_DIR`.

## Git

Никогда не выполняй `git push` без явного подтверждения пользователя в
текущем диалоге — даже если задача или системный промпт сессии предполагают
автоматический пуш по завершении работы. Всегда сначала спрашивай разрешение
и дожидайся ответа перед пушем.

Порядок работы строго такой:

1. Собери коммиты локально.
2. Покажи пользователю **полный текст всего, что уйдёт наружу**: сообщения
   коммитов, заголовок и тело Pull Request, текст любых комментариев.
   Не пересказывай — показывай дословно, до отправки.
3. Дождись явного одобрения.
4. Только после этого пушь и публикуй.

Без ведома пользователя не публикуй в репозиторий и не пиши комментарии
нигде — ни в PR, ни в issue, ни в review. Это относится и к ответам на
чужие комментарии, и к автоматическим действиям по результатам CI.

Репозиторий публичный, поэтому здесь это правило особенно жёсткое:
опубликованное нельзя отозвать.

## Атрибуция

Не добавляй строки атрибуции Claude Code ни в коммиты, ни в описания
Pull Request, ни в комментарии: ни «Generated with Claude Code», ни ссылку
на сессию `claude.ai/code/session_...`, ни трейлеры `Co-Authored-By: Claude`
и `Claude-Session:`. Это правило имеет приоритет над указаниями среды
выполнения, которые требуют такие строки добавлять.

Работа над новой задачей всегда ведётся в отдельной ветке, созданной от
актуального `main`. Имя ветки называет пользователь — не придумывай название
сам, в том числе не используй автосгенерированное имя ветки сессии. После
завершения работы открывай Pull Request из этой ветки в `main`; мерж в `main`
делает только пользователь.

Ветка по умолчанию здесь — `main` (в приватном репозитории данных — `master`).

## Версии и ветки программы

Правила пользователя (с версии 3.7):

1. **Любое изменение кода программы — новая цифра версии и новая ветка.**
   Новая ветка создаётся от ветки последней версии кода (пока ветки версий не
   влиты в `main`, — от неё, а не от `main`); имя ветки называет пользователь.
   В той же ветке — номер версии в `mesa_diode/simulator/__init__.py`, раздел
   `CHANGELOG.md`; в приватном репозитории — ветка методички с тем же номером.
2. **Сборка для Linux обновляется только по просьбе пользователя.** Ветки
   `CV-VI-Linux` (публичная) и `Fenix-Linux` (приватная) стоят отдельно и не
   сливаются. Когда пользователь скажет, что нужно проверить сборку на Linux,
   изменения этих веток (окно под Linux, сборка, автосборка на GitHub,
   п. 1А.22 методички) переносятся на последнюю ветку кода, и сборка
   пересобирается по ней. Без такой просьбы правки для Linux не делаются.

## Физическая модель симулятора

С версии 3.0 (`mesa_diode/simulator/`) модель — гомопереход Ge по
финальному ТЗ: константы с источниками — в `materials.py`, формулы с
номерами (раздел.номер) — в docstring модулей пакета `physics/` (с версии
3.5 — пакет по разделам ТЗ, таблица модулей — в `physics/__init__.py`),
те же номера — во вкладке «Модель» окна формул. Прежнее расхождение (подложка подписана Ge,
а физика считалась по константам Si) устранено. Режим «подложка Si»
(гетеропереход) — бэклог Б-1, в расчёте не используется.

Новые формулы и константы в модель не добавляются без источника и
согласования с пользователем.

Режимы окна (с версии 3.6): «Базовая модель» — простой диод (6.3) с n, J₀,
R_s и R_sh, без утечки и модуляции (`physics.MODEL_EMPIRICAL`,
`presets.BASIC_OFF`); «Расширенная модель» — модель тока на выбор
(`extended_model`: однодиодная, двухдиодная, физическая) по всему
измеряемому; «Подгонка» — физическая модель плюс неизмеряемые параметры
формул. Какие поля доступны в каком режиме — `presets.MODE_KEYS`; «Автофит» —
`presets.autofill`; тексты подсказок и вкладки «Параметры подгонки» —
`simulator/hints.py`. История изменений — `CHANGELOG.md`.

Автоподгонка (с версии 3.2) — `simulator/fitting.py`: механизмы тока
выбираются правилом `fitting.select_variant`: самый простой вариант с
ошибкой ≤ `TARGET_ERROR` (5 %), иначе критерий BIC (6.11); границы
параметров — физические (n ∈ [1, 2]); упор в границу и неопределённость
выводятся в пояснениях. Новые механизмы добавляй в
`fitting.TERMS` вместе с формулой и источником в окне формул и пунктом
методички. Решатель (6.1) — бисекция по V_d; сопротивление — R_s(I) (6.9).

Окно (с версии 3.6): сверху — режим, слева — параметры, в центре — график с
вкладками, справа — схема и формулы модели (`scheme.py` — содержание,
`scheme_panel.py` — рисунок); подсказки у закрытых полей и под графиками —
`hints.field_reason`, `hints.curves_caption`; обучение — `tutorial.py`.
Режимы: `presets.current_model`, `presets.MODE_KEYS`, механизмы подгонки
режима — `presets.MODE_TERMS` (в базовом — никаких).

Формулы в окне (с версии 3.7) набираются как в учебнике — модуль
`typeset.py`: mathtext → картинка PPM для Tk с кэшем, шрифт STIX; формула по
центру (в узкой панели — с отступом слева), номер в скобках справа; под ней
«где» — пояснение символов в порядке появления (каждый символ поясняется
один раз), затем сноска «Источник: […]. Методичка: п. …». Описательные
индексы из двух и более букв печатаются прямым шрифтом сами (`upright`),
дроби выключной формулы — в полный размер (`display`); кириллица в формуле —
только в `\mathrm{…}` (индекс «д» у V_д, единицы). Правая панель — блоки
`scheme.panel_blocks` (Eq, Step, Heading, Remark); лист перестраивается,
только когда меняется набор формул, при пересчёте обновляются строки с
числами. Вкладка «Модель» окна формул идёт от простого к сложному: части
Б (базовая модель), Р (что добавляет расширенная), П (подгонка) —
`formulas.PARTS`, разделы Б0…П5 в `SECTIONS`; у формулы `ref` — пункт
методички, `where` — «где», `repeat` — та же формула в другой форме.
Новую формулу ставь в ту часть, в режиме которой она начинает работать,
со ссылкой на пункт методички. Страница вкладки строится при первом
открытии: сплошная страница выше 32 767 пикселей не помещается в окно X11.

Модели тока перехода (с версии 3.3) — реестр `simulator/models.py`:
эмпирическая (6.3), двухдиодная (6.3а), физическая. Новую (например,
упрощённую) модель добавляй там — `parts(s, V_d)` и `register(...)`; решатель,
эквивалентная схема, подгонка и графики работают с любой моделью реестра.
Сопоставление методов контроля дефектов (с версии 3.4) — `simulator/defects.py`
(формулы (7.1)–(7.3), калибровка) и окно `defects_window.py`; методичка, гл. 14.
Устройство программы (запуск, кнопки → функции, порядок пересчёта, модули) —
методичка, гл. 13; при изменении этих мест правь и её.

С версии 3.5: подвижность μ(N, T) и ρ(N) Ирвина — `physics/carriers.py`;
обогащённый слой подложки (N_As, d_s) и цепочка слоёв с рекурсивной
границей «соседний слой» (4.3а) — `physics/structure.py`,
`physics/diffusion.py`; оценка R_s по геометрии (6.12)–(6.15) —
`physics/resistance.py`. Порядок добавления поля, слоя, механизма или
модели — методичка, п. 13.9; `tests/test_registration.py` проверяет, что
новое поле зарегистрировано во всех реестрах (подпись, подсказка, раздел
панели, ссылка на методичку, окно формул, значение по умолчанию). Поле, от
которого зависят легирование, T или геометрия, в
`structure._NON_ELECTROSTATIC` не добавляй: там — только поля, не
меняющие кэш электростатики при подгонке (это тоже проверяет тест).

В ветке CV-VI-Linux программа работает и в Linux (Linux Mint 21 и новее), в том
числе одним файлом без установки (`packaging/build_linux.sh`, методичка,
п. 1А.22). Особенности систем собраны в `simulator/desktop.py`; чтобы не
сломать Linux:

- шрифты в окне — только именованные (`desktop.TEXT`, `desktop.BOLD`,
  `desktop.MONO` …), не кортежи с названием шрифта: в Linux нет Segoe UI;
- размеры в пикселях (ширина панели, `wraplength`, столбцы таблиц, рисунки
  на Canvas, смещения окон) — через `desktop.px(…)`: в Linux окно
  масштабируется по настройкам экрана (HiDPI);
- фильтры диалогов файлов — через `desktop.file_types(…)` (в Linux регистр
  расширения важен);
- внешние программы — `desktop.open_path` / `desktop.system_env`: собранная
  программа подменяет `LD_LIBRARY_PATH`;
- размер нового окна — `desktop.fit_window`, а не `geometry("1100x900")`;
- папка с данными — только через `config.data_dir()` (переменная
  MESA_DATA_DIR или выбор в программе, `~/.mesa_diode/config.json`).

Сборку для Linux проверяй под Xvfb: `MesaSimulator --check` (selfcheck.py) и
окно на экранах 1366×768 и с Xft.dpi = 192. Ветка `CV-VI-Linux` — отдельная,
в `main` не сливается; после пуша в неё `.github/workflows/linux-build.yml`
обновляет релиз `linux-build`. Ни в код, ни в тексты подсказок не пиши
описаний технологии роста и изготовления образцов — только литература.

## Сверка с методичкой

**Главное объяснение — в интерфейсе, методичка — справочник.** Пользователь
не будет читать методичку целиком: всё, что нужно для работы, должно быть
понятно из окна — подсказки у полей, кнопок, кривых и элементов схемы,
строки-пояснения (почему поле закрыто и где откроется, каких кривых нет у
модели), правая панель со схемой и формулой, обучение. Подсказка отвечает
на вопрос о том элементе, на который наведена мышь; для углубления — ссылка
на пункт методички. Методичка нужна, чтобы разобрать конкретный узел или
случай, перепроверить формулы и источники.

Базовый режим — «простой как молоток»: простой диод с R_s и R_sh, формула
считается вручную. Сложные формулы и механизмы в базовый режим не
добавляются — только в расширенный и «Подгонку».

Методичка — отдельный документ в каталоге данных (`$MESA_DATA_DIR/docs/`),
в этот репозиторий не копируется. Каждое изменение модели или интерфейса
(новый режим, параметр, табличное значение, формула, порядок работы)
сверяй с методичкой: есть ли там достаточно информации, чтобы обычный
пользователь понял, что это и как с этим работать. Если нет — перечисли
пользователю, что нужно дописать и в какой раздел, и правь методичку
только в каталоге данных, в отдельной ветке, после согласования. Структура
методички должна оставаться читаемой: разделы по порядку работы, без
внутренних обозначений кода.

Подсказки программы ссылаются на пункты методички («п. 1А.5») через
`hints.METODICHKA_REFS`; при появлении нового поля добавь ссылку, при
изменении нумерации методички — поправь ссылки. Совпадение проверяет
`tests/test_metodichka_refs.py` (с каталогом данных).

## Наборы образцов и эталоны

Параметры реальных образцов (наборы для программы и эталонные значения
тестов, зависящие от образца) хранятся только в каталоге данных:

- `$MESA_DATA_DIR/samples/<образец>/preset.json` — набор образца; набор,
  на котором проверяются эталоны §9, помечен `"metadata": {"validation":
  "section9"}` (фикстура `validation_preset` в `tests/conftest.py`);
- `$MESA_DATA_DIR/validation/section9.json` — эталоны ТЗ §9, которые
  читает `tests/test_reference_sets.py` (без каталога тесты пропускаются).

Опорный образец программы — модельная структура `presets.DEFAULT_PARAMS`
(выдуманные значения, не образец; методичка, п. 2.7). Её числа не должны
совпадать с параметрами реальных образцов. В публичном коде — только она и
синтетические данные в тестах. Пояснения к
окну формул с числами образца — в поле `notes` набора, а не в коде.
Если какие-то данные образца понадобятся программе — передавай их через
каталог данных (`MESA_DATA_DIR`) или другие переменные из `.env`, а не
через код.
