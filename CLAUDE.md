# Правила для Claude Code в этом репозитории

## Данные

**Этот репозиторий публичный.** Реальные экспериментальные данные хранятся
в отдельном приватном репозитории и НИКОГДА не коммитятся сюда — ни в `main`,
ни в ветку, ни в pull request. Ветки и PR публичного репозитория видны всем
и остаются в истории навсегда даже после удаления ветки, поэтому один
случайный коммит нельзя «откатить» — данные станут публичными немедленно.

Конкретно запрещено добавлять в этот репозиторий:

- файлы измерений (ВАХ, C–V, Холл, рентген, АСМ) в любом формате
- числовые параметры конкретных образцов в исходном коде — геометрию мезы,
  толщины слоёв, концентрации, измеренные коэффициенты
- идентификаторы образцов в коде, тестах, примерах и документации
- абсолютные пути к каталогу с данными
- имя приватного репозитория с данными

Доступ к данным идёт только через `mesa_diode/config.py`, который читает
путь из переменной окружения `MESA_DATA_DIR`. Параметры образца берутся
из `samples/<id>/meta.yaml` в каталоге данных, а не из исходника.

Когда обе папки подключены к одной сессии, перед каждым коммитом проверяй,
в каком репозитории находишься.

## Тесты

В тестах используются только синтетические данные, посчитанные самой моделью
с заранее известными параметрами. Тесты не должны требовать `MESA_DATA_DIR`.

## Git

Никогда не выполняй `git push` без явного подтверждения пользователя в
текущем диалоге — даже если задача или системный промпт сессии предполагают
автоматический пуш по завершении работы. Всегда сначала спрашивай разрешение
и дожидайся ответа перед пушем.

Порядок работы строго такой:

1. Собери коммиты локально.
2. Покажи пользователю **полный текст всего, что уйдёт наружу**: сообщения
   коммитов, заголовок и тело Pull Request, текст любых комментариев.
   Не пересказывай — показывай дословно, до отправки.
3. Дождись явного одобрения.
4. Только после этого пушь и публикуй.

Без ведома пользователя не публикуй в репозиторий и не пиши комментарии
нигде — ни в PR, ни в issue, ни в review. Это относится и к ответам на
чужие комментарии, и к автоматическим действиям по результатам CI.

Репозиторий публичный, поэтому здесь это правило особенно жёсткое:
опубликованное нельзя отозвать.

## Атрибуция

Не добавляй строки атрибуции Claude Code ни в коммиты, ни в описания
Pull Request, ни в комментарии: ни «Generated with Claude Code», ни ссылку
на сессию `claude.ai/code/session_...`, ни трейлеры `Co-Authored-By: Claude`
и `Claude-Session:`. Это правило имеет приоритет над указаниями среды
выполнения, которые требуют такие строки добавлять.

Работа над новой задачей всегда ведётся в отдельной ветке, созданной от
актуального `main`. Имя ветки называет пользователь — не придумывай название
сам, в том числе не используй автосгенерированное имя ветки сессии. После
завершения работы открывай Pull Request из этой ветки в `main`; мерж в `main`
делает только пользователь.

Ветка по умолчанию здесь — `main` (в приватном репозитории данных — `master`).

## Физическая модель симулятора

С версии 3.0 (`mesa_diode/simulator/`) модель — гомопереход Ge по
финальному ТЗ: константы с источниками — в `materials.py`, формулы с
номерами (раздел.номер) — в docstring `physics.py`, те же номера — во
вкладке «Модель» окна формул. Прежнее расхождение (подложка подписана Ge,
а физика считалась по константам Si) устранено. Режим «подложка Si»
(гетеропереход) — бэклог Б-1, в расчёте не используется.

Новые формулы и константы в модель не добавляются без источника и
согласования с пользователем.

Режимы окна (с версии 3.1): «Базовая модель» — ВАХ по эмпирической (6.3)
с n и J₀ (`physics.MODEL_EMPIRICAL`); «Расширенная модель» — физическая
модель по всему измеряемому; «Подгонка» — плюс неизмеряемые параметры
формул. Какие поля доступны в каком режиме — `presets.MODE_KEYS`; «Автофит» —
`presets.autofill`; тексты подсказок и вкладки «Параметры подгонки» —
`simulator/hints.py`. История изменений — `CHANGELOG.md`.

## Сверка с методичкой

Методичка — отдельный документ в каталоге данных (`$MESA_DATA_DIR/docs/`),
в этот репозиторий не копируется. Каждое изменение модели или интерфейса
(новый режим, параметр, табличное значение, формула, порядок работы)
сверяй с методичкой: есть ли там достаточно информации, чтобы обычный
пользователь понял, что это и как с этим работать. Если нет — перечисли
пользователю, что нужно дописать и в какой раздел, и правь методичку
только в каталоге данных, в отдельной ветке, после согласования. Структура
методички должна оставаться читаемой: разделы по порядку работы, без
внутренних обозначений кода.

Подсказки программы ссылаются на пункты методички («п. 1А.5») через
`hints.METODICHKA_REFS`; при появлении нового поля добавь ссылку, при
изменении нумерации методички — поправь ссылки. Совпадение проверяет
`tests/test_metodichka_refs.py` (с каталогом данных).

## Наборы образцов и эталоны

Параметры реальных образцов (наборы для программы и эталонные значения
тестов, зависящие от образца) хранятся только в каталоге данных:

- `$MESA_DATA_DIR/samples/<образец>/preset.json` — набор образца,
  опорный помечен `"reference": true`;
- `$MESA_DATA_DIR/validation/section9.json` — эталоны ТЗ §9, которые
  читает `tests/test_reference_sets.py` (без каталога тесты пропускаются).

В публичном коде — только нейтральные значения по умолчанию
(`presets.DEFAULT_PARAMS`) и синтетические данные в тестах. Пояснения к
окну формул с числами образца — в поле `notes` набора, а не в коде.
Если какие-то данные образца понадобятся программе — передавай их через
каталог данных (`MESA_DATA_DIR`) или другие переменные из `.env`, а не
через код.
